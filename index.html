Part 1 · Prerequisites

1

Open PowerShell as Administrator

What you are doing

Opening an elevated PowerShell window. Every command in this lab runs in PowerShell, and installations need administrator rights.

What to expect

A PowerShell window opens with Administrator: Windows PowerShell in the title bar.

  1. Select Start and type PowerShell.
  2. Right-click Windows PowerShell.
  3. Select Run as administrator.
  4. Select Yes in the User Account Control prompt.
Terminal 1. This is your first terminal. You will use it to start the MCP server later.
2

Check Node.js and npm

What you are doing

Confirming Node.js and npm are installed. The MCP server runs with npx, which comes with npm.

What to expect

Each command prints a version number. Your versions may be newer.

PowerShell
node --version
PowerShell
npm --version

If either command is not recognized, install Node.js LTS:

PowerShell
winget install --id OpenJS.NodeJS.LTS -e
After installing: close PowerShell, open it again as Administrator, and rerun both checks.
3

Check Work IQ Dev Tools (WIQD)

What you are doing

Confirming the WIQD command-line tool is installed. WIQD creates, provisions and packages the Cowork plugin.

What to expect

A version number is printed.

PowerShell
wiqd --version

If WIQD is not recognized, install it:

PowerShell
iex "& { $(irm 'https://aka.ms/wiqd/install.ps1') }"

If WIQD shows Update available, update it:

PowerShell
wiqd update
After installing or updating: close PowerShell, reopen it as Administrator and run wiqd --version again.
4

Check Microsoft Dev Tunnels CLI

What you are doing

Confirming the Dev Tunnels CLI is installed. Dev Tunnels gives your local MCP server a public HTTPS URL that Cowork can reach.

What to expect

The tunnel CLI version and tunnel service details are printed.

PowerShell
devtunnel --version

If devtunnel is not recognized, install it:

PowerShell
winget install --id Microsoft.devtunnel -e
After installing: close PowerShell, reopen it as Administrator and run devtunnel --version again.
5

Confirm your Cowork access

What you are doing

Making sure the account you will sign in with can use Cowork and plugins.

What to expect

You can open Cowork and see Plugins in the left navigation.

Use the work or school account provided for the lab. You will sign in with this account in WIQD and in Cowork.

Checkpoint: Node.js, npm, WIQD and Dev Tunnels all return versions, and Cowork opens with your lab account.

Part 2 · Database, MCP server and Dev Tunnel

6

Create the lab folder

What you are doing

Creating a dedicated folder for the Northwind database and plugin project.

What to expect

PowerShell switches to C:\Northwind-Cowork-Lab.

In terminal 1 (Administrator), run:

PowerShell
mkdir C:\Northwind-Cowork-Lab
View reference output
PowerShell
cd C:\Northwind-Cowork-Lab
View reference output
7

Download the Northwind database

What you are doing

Downloading Northwind as a single SQLite file. No database server, Azure subscription or account is required.

What to expect

curl shows a 100% download and northwind.db appears in the folder.

PowerShell
curl.exe -L -o northwind.db https://raw.githubusercontent.com/jpwhite3/northwind-SQLite3/main/dist/northwind.db
View reference output

Confirm the file exists:

PowerShell
dir northwind.db
Checkpoint: northwind.db is listed with a size of about 23 MB.
8

Start the Northwind MCP server

What you are doing

Starting an MCP server over the database. mcp-sqlite exposes the database tools, and supergateway makes them available over HTTP on port 3000.

What to expect

The output ends with Listening on port 3000 and the endpoint http://localhost:3000/mcp.

In terminal 1, from C:\Northwind-Cowork-Lab, run:

PowerShell
npx -y supergateway --stdio "npx -y mcp-sqlite ./northwind.db" --outputTransport streamableHttp --port 3000
View reference output
Keep terminal 1 open. Do not close it or press Ctrl+C. Closing it stops the database connection for your plugin.
9

Sign in to Dev Tunnels and host the tunnel

What you are doing

Publishing your local MCP server through a secure public HTTPS URL so Cowork can reach it.

What to expect

After sign-in, the host command prints a Connect via browser URL and Ready to accept connections.

Open a second PowerShell as Administrator. Keep terminal 1 running. Repeat Step 1 to open terminal 2.

Sign in to Dev Tunnels:

PowerShell
devtunnel user login

A browser window opens. Sign in with your account and return to PowerShell when sign-in completes.

Then host port 3000:

PowerShell
devtunnel host -p 3000 --allow-anonymous
View reference output
Copy your lab URL. Use the URL in the format https://<id>-3000.<region>.devtunnels.ms. Your value will be different. You will add /mcp to it in Step 12.
Keep terminal 2 open. You should now have two running terminals.

Part 3 · Build the plugin with WIQD

10

Create the WIQD plugin project

What you are doing

Using WIQD to scaffold a new plugin project with the manifest, environment files and folder structure.

What to expect

WIQD creates the northwind-cowork-plugin folder.

Open a third PowerShell as Administrator. Keep terminals 1 and 2 running. This is terminal 3.

View reference output

wiqd plugin create --name northwind-cowork-plugin
View reference output
PowerShell
cd C:\Northwind-Cowork-Lab\northwind-cowork-plugin
View reference output
11

Create toolDescription.json in Notepad

What you are doing

Describing the four database tools to Cowork: list tables, describe a table, read data and update data. Each tool needs an inputSchema.

What to expect

toolDescription.json is saved inside the appPackage folder.

In terminal 3, open a new file in Notepad:

PowerShell
notepad .\appPackage\toolDescription.json

When Notepad asks to create the file, select Yes. Copy the JSON below, paste it into Notepad, then select File > Save and close Notepad.

JSON
{
  "name": "Northwind Traders DB",
  "description": "Query and update Northwind Traders customers, orders, and inventory records.",
  "tools": [
    {
      "name": "list_tables",
      "description": "List all tables in the Northwind database.",
      "inputSchema": {
        "type": "object",
        "properties": {}
      }
    },
    {
      "name": "describe_table",
      "description": "Get column names and schema details for a table in Northwind.",
      "inputSchema": {
        "type": "object",
        "properties": {
          "table_name": {
            "type": "string",
            "description": "Name of the Northwind table to describe."
          }
        },
        "required": ["table_name"]
      }
    },
    {
      "name": "read_query",
      "description": "Execute a SELECT SQL query to pull records from Northwind.",
      "inputSchema": {
        "type": "object",
        "properties": {
          "query": {
            "type": "string",
            "description": "The SELECT SQL query to execute."
          }
        },
        "required": ["query"]
      }
    },
    {
      "name": "write_query",
      "description": "Execute an INSERT, UPDATE, or DELETE SQL query to update Northwind records.",
      "inputSchema": {
        "type": "object",
        "properties": {
          "query": {
            "type": "string",
            "description": "The INSERT, UPDATE, or DELETE SQL query to execute."
          }
        },
        "required": ["query"]
      }
    }
  ]
}

Confirm the file was saved:

PowerShell
dir .\appPackage
View reference output
Keep the filename exactly toolDescription.json. Make sure Notepad did not save it as toolDescription.json.txt.
12

Add the Northwind connector

What you are doing

Registering your public MCP endpoint as a remote connector and linking it to the tool description.

What to expect

WIQD adds the NorthWindDB connector to the plugin manifest.

Replace <YOUR-LAB-URL> with the Dev Tunnel URL from Step 9. Keep /mcp at the end with no space.

PowerShell
wiqd plugin add connector --name "NorthWindDB" --description "Northwind Traders Order Management Database" --url "<YOUR-LAB-URL>/mcp" --tool-description ./appPackage/toolDescription.json
View reference output
Checkpoint: The connector URL ends with /mcp.
13

Add the order-manager skill and edit SKILL.md

What you are doing

Adding a skill that tells Cowork how to use the Northwind tools: check the schema, read records into a table, and verify any update.

What to expect

WIQD creates appPackage\skills\order-manager\SKILL.md and registers it in the manifest. You then replace its content.

Create the skill:

PowerShell
wiqd plugin add skill --name "order-manager"
View reference output

Open the generated skill file in Notepad:

PowerShell
notepad .\appPackage\skills\order-manager\SKILL.md

Select all existing text and delete it. Copy the content below, paste it into Notepad, then select File > Save and close Notepad.

Markdown
---
name: order-manager
description: Query and update customer orders in Northwind Traders.
---

When the user asks about orders or customers:
- Always run list_tables and describe_table first if you are unsure of exact column names.
- Use read_query to fetch matching records and present them in a clean markdown table.
- When asked to update or ship an order, execute write_query with a targeted UPDATE statement and verify the change with a follow-up read_query.
Keep the skill name and folder the same: order-manager. A mismatch causes a Missing packaging reference error during provisioning.

Part 4 · Test in Cowork

17

Enable the plugin in Cowork

What you are doing

Turning on your Northwind plugin so Cowork can use its connector and skill.

What to expect

The plugin shows as on, with the NorthWindDB connector and order-manager skill listed.

1. Open Plugins. In Cowork, select Plugins in the left navigation. This lists the plugins available to your account, including the one you just provisioned.

View reference output

2. Find your plugin. Locate the Northwind plugin and select it to open its details. If you do not see it, refresh the page. Provisioning can take a moment to appear.

View reference output

3. Turn it on. Switch the plugin on and confirm that the details page lists the NorthWindDB connector and the order-manager skill. These come from Steps 12 and 13.

View reference output
18

Run the test prompt

What you are doing

Asking Cowork a natural-language question that it answers by calling your MCP tools against the Northwind database.

What to expect

Cowork asks permission to use the tools, runs a read-only SQL query and returns five unshipped orders in a table.

1. Submit the prompt. Start a new Cowork conversation and paste:

Prompt
Using Northwind DB list the 5 unshipped orders along with their order id, customer id and freight cost
View reference output

2. Approve the schema request. Cowork first follows the skill instructions and asks to inspect the table structure, so it uses the correct column names. Review the request and approve it.

View reference output

3. Review and approve the SQL query. Cowork shows the SELECT query it will run with read_query. It only reads data. Check that it filters for unshipped orders, then approve it.

View reference output

4. Review the result. Cowork returns the order ID, customer ID and freight cost for five unshipped orders in a table. You can also watch the request appear in terminals 1 and 2.

View reference output
