Set-Location C:\

Open expected response

The source project can contain development files such as lifecycle and environment configuration. Do not delete them. WIQD uses them later for provisioning and packaging.

7

Add the Critical Support Skill

Add the Skill with WIQD

wiqd plugin add skill --name "Critical Support Escalation"

Find the generated SKILL.md

$skillFile = (Get-ChildItem -Path . -Filter SKILL.md -Recurse | Select-Object -First 1).FullName

Write the Skill instructions

@'
---
name: critical-support-escalation
description: Investigate critical ServiceNow incidents and prepare evidence-backed coordinated actions.
---

# Critical Support Escalation

1. Retrieve the relevant critical incidents.
2. Compare symptoms, affected services, priorities, states, and notes.
3. Group incidents only when the evidence supports a relationship.
4. Keep uncertain incidents separate.
5. Search for relevant Known Error resolutions.
6. Recommend a coordinated action supported by evidence.
7. Do not add a work note or modify an incident without explicit user confirmation.
8. Do not invent incident details.
'@ | Set-Content -Path $skillFile -Encoding utf8
Open expected response

PowerShell normally returns to the prompt without displaying output.

8

Add the MCP connector and pin its tools

Set the instructor-provided MCP URL

$env:LAB_MCP_URL = "<YOUR-GROUP-DEV-TUNNEL-URL>/mcp"
Check: The URL must end with /mcp.

Add the connector with WIQD

wiqd plugin add connector `
  --name "ServiceNow Critical Support" `
  --description "Retrieve critical incidents, inspect tickets, search Known Error resolutions, and add confirmed work notes." `
  --url $env:LAB_MCP_URL

Create the tools folder inside the app package

$appPackage = (Get-ChildItem -Path . -Directory -Filter appPackage -Recurse | Select-Object -First 1).FullName
New-Item -ItemType Directory -Path (Join-Path $appPackage 'tools') -Force

Create servicenow-critical-tools.json

@'
{
  "tools": [
    {
      "name": "get_critical_incidents",
      "description": "Retrieve critical ServiceNow incidents for investigation.",
      "inputSchema": {"type":"object","properties":{},"additionalProperties":false}
    },
    {
      "name": "get_incident",
      "description": "Retrieve a ServiceNow incident by incident number.",
      "inputSchema": {
        "type":"object",
        "properties":{"incident_number":{"type":"string"}},
        "required":["incident_number"],
        "additionalProperties":false
      }
    },
    {
      "name": "search_known_errors",
      "description": "Search Known Error information for evidence-backed resolutions.",
      "inputSchema": {
        "type":"object",
        "properties":{"query":{"type":"string"}},
        "required":["query"],
        "additionalProperties":false
      }
    },
    {
      "name": "add_work_note",
      "description": "Add a confirmed coordinated work note to a ServiceNow incident.",
      "inputSchema": {
        "type":"object",
        "properties":{"incident_number":{"type":"string"},"work_note":{"type":"string"}},
        "required":["incident_number","work_note"],
        "additionalProperties":false
      }
    }
  ]
}
'@ | Set-Content -Path (Join-Path $appPackage 'tools\servicenow-critical-tools.json') -Encoding utf8
Instructor check: The pinned names and schemas above must match the tools exposed by the lab MCP server.
9

Update manifest.json in PowerShell

WIQD created the manifest. Keep its generated app identity and schema. Use PowerShell to update only the remote MCP connector and pinned-tool reference.

Locate manifest.json

$manifestFile = Join-Path $appPackage 'manifest.json'

Load the manifest

$manifest = Get-Content $manifestFile -Raw | ConvertFrom-Json

Find the remote MCP server configuration

$remoteMcpServer = $manifest.agentConnectors[0].toolSource.remoteMcpServer

Set the MCP server URL

$remoteMcpServer.mcpServerUrl = $env:LAB_MCP_URL

Add the pinned tools file

$remoteMcpServer | Add-Member `
  -NotePropertyName mcpToolDescription `
  -NotePropertyValue @{ file = 'tools/servicenow-critical-tools.json' } `
  -Force

Save manifest.json

$manifest | ConvertTo-Json -Depth 20 | Set-Content $manifestFile -Encoding utf8

Review the updated manifest

Get-Content $manifestFile
Open expected result

The existing remoteMcpServer object should now contain:

"mcpServerUrl": "<YOUR-GROUP-DEV-TUNNEL-URL>/mcp", "mcpToolDescription": { "file": "tools/servicenow-critical-tools.json" }
No editor required: All manifest changes are completed in PowerShell. Do not replace the manifest ID or schema generated by WIQD.

Inspect the final plugin package

The WIQD source project can contain lifecycle/environment files. The packaged plugin ZIP is the artifact participants should understand and share.

Extract the package for inspection

$inspect = Join-Path $env:TEMP 'Critical-Support-Escalation-Package'
Remove-Item $inspect -Recurse -Force -ErrorAction SilentlyContinue
Expand-Archive -Path $zip -DestinationPath $inspect
tree $inspect /F
Open required final package structure

The plugin payload should contain these plugin assets:

Critical-Support-Escalation-Cowork ├── skills │ └── critical-support-escalation │ └── SKILL.md ├── tools │ └── servicenow-critical-tools.json ├── color.png ├── manifest.json └── outline.png

This is the final plugin structure participants need to understand. The WIQD lifecycle files remain outside the packaged plugin.
